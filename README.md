# jepo｜打烊清潔照，不用再一張一張整理

門市打烊後要上傳不少清潔照片。照片常常分不同區域，傳錯資料夾或重複上傳都很麻煩。這個工具就是想把「選照片 → 分類 → 壓縮 → 檢查重複 → 上傳」變成比較順手的一次操作。

**[回到面試作品集](https://github.com/garyai8146-jpg/Yihop_LineBOT/blob/main/PORTFOLIO.md)**

## 做了哪些事

- 前場與後場照片可以分開累積，不用一次選完。
- 使用 Pillow 將圖片轉成壓縮 JPEG，降低上傳量。
- 用檔案內容 MD5 和 Google Drive 的檢查碼比對，減少完全相同照片的重複上傳。
- 同一批次也會預先比對 MD5，避免多個上傳執行緒同時提交同一張圖片。
- 自動尋找或建立對應 Google Drive 資料夾，再透過 ThreadPoolExecutor 並行上傳。

## 如何啟動

```powershell
python -m pip install -r requirements.txt
streamlit run app.py
```

使用時在左側上傳**自己的 Google OAuth 使用者憑證 JSON 檔**，再填入目標 Google Drive 資料夾 ID。這次修正之後，程式**不再把 OAuth 權杖寫進伺服器的 `drive_config.json`**，而是只暫存在當次的 Streamlit 工作階段；斷線或重新建立工作階段後需要再次連線。

**舊版使用者注意：** 之前產生的 `drive_config.json` 不會自動清除，升級時請從伺服器端手動刪除，必要時撤銷舊授權。不要將憑證檔、門市照片或客戶資料上傳至 GitHub。這個原型適合在可信任的本機環境測試，不建議直接對不可信任的網路開放。

## 這個工具的難點

「一模一樣的檔案」和「看起來是一樣的照片」不是同一回事。MD5 只能比對檔案內容；重新拍照或重新壓縮之後，檢查碼就可能不同。

另一個問題是批次上傳的失敗回報：並行處理雖然能加快速度，但每張照片是否成功、要不要重試，都需要清楚記錄。這次也把「同一批照片的重複提交」納入檢查。

## 測試與限制

GitHub Actions 目前會執行 Python 語法、憑證不落地及批次去重邏輯的離線回歸測試。實際上傳仍取決於 Google OAuth 權限、API 配額和網路，尚未宣稱已完成多使用者公開部署驗收。
